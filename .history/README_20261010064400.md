# SIMTANI

SIMTANI adalah aplikasi Laravel untuk mengelola anggota, jadwal pertanian, penugasan, presensi, upah, permintaan perubahan, dan laporan.

## Menyiapkan database MySQL Laragon

Setiap developer memakai database lokalnya sendiri. Setelah mengambil perubahan terbaru dari Git:

1. Jalankan MySQL dari Laragon.
2. Buat database baru bernama `simtani` melalui phpMyAdmin, atau jalankan SQL berikut:

   ```sql
   CREATE DATABASE IF NOT EXISTS simtani
     CHARACTER SET utf8mb4
     COLLATE utf8mb4_unicode_ci;
   ```

3. Pastikan `.env` memakai koneksi MySQL berikut. Jika `.env` sudah ada, ubah bagian database tanpa menimpa pengaturan lain:

   ```dotenv
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=simtani
   DB_USERNAME=root
   DB_PASSWORD=
   ```

4. Dari folder proyek, jalankan:

   ```bash
   composer install
   php artisan config:clear
   php artisan migrate --seed
   ```

   `migrate` akan menerapkan migrasi yang belum berjalan. `--seed` membuat atau memperbarui data contoh SIMTANI. Perintah ini aman dijalankan lagi untuk menyelaraskan perubahan schema dan data contoh.

5. Jalankan aplikasi:

   ```bash
   php artisan serve
   ```

### Apakah harus migrate lagi?

- **Ya**, jika database MySQL di komputer teman belum memiliki tabel terbaru atau belum berisi data contoh: jalankan `php artisan migrate --seed`.
- **Tidak perlu melakukan apa pun pada database** jika teman hanya mengubah tampilan dan memakai schema database yang sudah paling baru.
- Jika ada migrasi baru dari Git, jalankan `php artisan migrate --seed` lagi untuk menerapkannya. Laravel hanya menjalankan migrasi yang belum tercatat.
- Buat database lokal bernama `simtani` pada setiap komputer. Jangan sambungkan semua developer ke database produksi atau database bersama untuk pekerjaan lokal.
- **Jangan gunakan `php artisan migrate:fresh` untuk penyelarasan rutin.** Perintah itu menghapus seluruh tabel dan data di database yang sedang aktif.

Jika `.env` belum tersedia, salin `.env.example` terlebih dahulu. Buat `APP_KEY` hanya saat menyiapkan instalasi baru yang belum memiliki key:

```bash
php artisan key:generate
```

## Akun data contoh

| Peran | Email | Kata sandi |
|---|---|---|
| Admin | `admin.david@simtani.local` | `david12345` |
| Anggota | `dedi.prasetyo@simtani.local` | `anggota123` |

Seeder juga menyediakan anggota aktif dan nonaktif, kategori pekerjaan, jadwal, penugasan, presensi, upah, dan permintaan perubahan yang saling terkait. Data ini hanya untuk pengembangan lokal.

### Mengulang data contoh

Untuk membuat ulang atau memperbarui data contoh tanpa menghapus seluruh isi database:

```bash
php artisan db:seed
```

Seeder menggunakan `updateOrCreate`, jadi data contoh yang sudah ada akan diperbarui. Data lain yang dibuat di luar seeder tidak dihapus.

Jika ingin mengosongkan database lokal lalu memasang ulang semua tabel, migrasi, dan data contoh, jalankan:

```bash
php artisan migrate:fresh --seed
```

**Perhatian:** `migrate:fresh` menghapus semua tabel beserta seluruh data di database yang sedang aktif. Gunakan hanya pada database lokal/demo yang boleh dihapus; pastikan `.env` menunjuk ke database lokal `simtani` dan cadangkan data penting terlebih dahulu. Jangan jalankan pada database produksi atau database bersama.

## Menjalankan frontend

Frontend menggunakan halaman Blade Laravel dan aset di `public/`. Untuk menjalankan Vite saat mengembangkan aset:

```bash
npm install
npm run dev
```

### Catatan pekerjaan frontend

Alur utama sudah tersedia di aplikasi. Daftar berikut adalah tindak lanjut untuk pemeriksaan dan penyempurnaan tampilan, bukan klaim bahwa alur tersebut belum berfungsi:

- Uji tampilan di ponsel dan desktop, terutama tabel jadwal, penugasan, presensi, dan upah. Pastikan informasi penting serta tombol aksi tetap mudah ditemukan pada layar sempit.
- Rapikan konsistensi hierarki tombol dan teks pada detail tugas: anggota perlu membaca detail sebelum bertindak, dengan tombol check-in dan check-out terpisah serta konfirmasi sebelum masing-masing tindakan.
- Periksa tampilan status jadwal, tugas, presensi, permintaan perubahan, dan pembayaran. Gunakan label yang mudah dipahami, bukan nilai internal seperti `in_progress` atau `belum_dibayar`.
- Tinjau formulir izin/tidak hadir dan pengganti: alasan izin, tanggal yang terdampak, dan tindakan admin untuk mengisi kekurangan anggota harus jelas.
- Periksa kartu dashboard admin agar angka status mudah dipahami dan tautannya membuka daftar yang sudah terfilter sesuai label kartu.
- Uji keadaan kosong, validasi yang gagal, serta pesan berhasil/gagal; pastikan fokus keyboard, label formulir, kontras, dan ukuran area tombol memadai bagi pengguna yang kurang terbiasa dengan aplikasi.
- Hindari mengubah aturan bisnis atau alur backend saat merapikan tampilan tanpa menyepakati perubahan tersebut terlebih dahulu.

## Alur penugasan

1. `assigned`: anggota ditugaskan.
2. `in_progress`: anggota memulai pekerjaan.
3. `waiting_verification`: anggota mengirim laporan pekerjaan selesai.
4. `completed`: admin memverifikasi pekerjaan; upah otomatis dibuat dari tarif kategori dikalikan jumlah satuan jadwal.

Presensi terhubung ke penugasan. Status izin atau tidak hadir tercatat sebagai konteks, tetapi keputusan verifikasi pekerjaan tetap dilakukan admin.

## Fitur

### Admin

- Mengelola anggota aktif/nonaktif, kategori pekerjaan, jadwal, dan penugasan.
- Membuat penugasan otomatis berdasarkan kompetensi, bentrok jadwal, dan beban tugas; atau menambahkan anggota manual ke slot yang tersedia.
- Melihat presensi, memverifikasi pekerjaan, dan mengelola upah serta status pembayaran.
- Meninjau permintaan pertukaran atau sanggah tugas.
- Memfilter laporan jadwal, penugasan, presensi, dan upah; mengekspor CSV atau mencetak/menyimpan PDF.

### Anggota

- Melihat tugas, jadwal, dan anggota lain pada kegiatan yang sama.
- Memulai tugas, mencatat presensi, check-in/check-out, dan mengirim laporan selesai.
- Melihat upah setelah pekerjaan diverifikasi serta status pembayaran.
- Mengajukan dan memantau permintaan perubahan penugasan.
